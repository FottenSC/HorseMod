### World-registry hash layout resolved for the test boundary

The previously retained description of a *linear TArray search* was imprecise. I read the existing `SoulcaliburVI.exe` Ghidra program's `142018870` lookup, `140E69A30` insertion, `141DD4880` removal, `141C65AD0` sparse-slot allocation, `1411E1020` free-list removal and `141D01080` rehash. All use the same base pointer `&g_pWorldContextEntries` (`14406E4E0`) with no caller adjustment. The 0x18-byte row stride and matching insert/remove link writes independently verify the layout. No Ghidra struct was created or propagated because this was a read-only type investigation.

I corrected the directly relevant `GetBattleManagerFromWorldContext` (`1403EF7A0`) Ghidra plate comment, which had called the registry a linear TArray. I renamed its lookup callee at `142018870` to `FindWorldContextRegistryIndexByWorld` and added a plate comment covering buckets, sparse rows, collision links, and the native lookup's lack of independent occupancy/bounds checks. Both comments and the rename were read back and saved. No function prototype or datatype changed.

| Registry offset | Width | Verified role |
| --- | ---: | --- |
| +`0x00` | 8 | Pointer to 0x18-byte sparse row backing. |
| +`0x08` / +`0x0C` | 4 each | Allocated slot count/high-water index; row capacity. Live count is slots minus free count. |
| +`0x10..0x1F` | 16 | Four inline 32-bit occupancy words. |
| +`0x20` | 8 | Optional heap occupancy words, replacing the inline words when nonnull. |
| +`0x28` / +`0x2C` | 4 each | Occupancy-bit count and capacity in bits. |
| +`0x30` / +`0x34` | 4 each | Free-list head index and free-slot count. |
| +`0x38..0x3F` | 8 | Two inline 32-bit hash bucket heads. |
| +`0x40` | 8 | Optional heap bucket heads, replacing inline heads when nonnull. |
| +`0x48` | 4 | Power-of-two bucket count; upper four bytes remain untyped. |

For row index `i`, row address is backing+`i*0x18`. A live row has world pointer +`0x00`, battle-manager pointer +`0x08`, next collision-chain index `int32` +`0x10`, and cached bucket index `uint32` +`0x14`. A removed row reuses its first eight bytes as free-list links, so a census must verify the occupancy bit before interpreting its world/manager. The lookup first returns absent if allocated slots equal free slots. Otherwise it hashes `uint32(world >> 4)` with the game's 32-bit mixing sequence, masks by `bucket_count-1`, reads the head from the inline/heap bucket array, and follows row+`0x10` until `-1`, comparing row+`0x00` to the exact world pointer. `140E69A30` writes the same bucket/next fields on insert; `141DD4880` unlinks the matched row, and `141D01080` rebuilds buckets by occupied bits. This is not a dense scan or a direct listener field.

The exact 32-bit mixer in lookup `142018870` is reproducible without a one-bucket shortcut. All intermediate operations wrap as `uint32_t`; shifts are logical right shifts:

```cpp
uint32_t i = uint32_t(world >> 4);
uint32_t a = (0x9e3779b9u - i) ^ (i << 8);
uint32_t b = (0u - (a+i)) ^ (a >> 13);
uint32_t c = ((i-a)-b) ^ (b >> 12);
a = ((a-c)-b) ^ (c << 16);
b = ((b-a)-c) ^ (a >> 5);
c = ((c-a)-b) ^ (b >> 3);
a = ((a-c)-b) ^ (c << 10);
uint32_t bucket = (((b-a)-c) ^ (a >> 15)) & (bucket_count-1);
```

The native lookup itself trusts bucket/row invariants and does not independently check occupancy bits, bounds or cycles. A bounded observer reading an unowned registry must enforce those checks and report incomplete evidence on corruption. A production census restricted to a single bucket would not cover the likely live registry; use the actual mixer with a bounded power-of-two bucket count for useful live observation.

The registry's bucket-sizing helper `141CF3D90` yields one bucket while live count is 1–3. At live count 4 it grows to 16 buckets; count 4–17 retains 16, then count 18 grows to 32. For a fixture intended to model a normal native-produced multi-bucket table, use four occupied rows and 16 buckets rather than an arbitrary four-bucket table. A deliberately malformed table can be a negative control, but must not be described as normal insertion output.

For a bounded fixture, one occupied row with bucket count 1 is a valid native shape: inline bucket[0] points to that row, its next index is `-1`, occupancy bit 0 is set, allocated count and bit count are 1, free count is 0. The fixture must still present the row/world/manager chain to production; it must not return a preselected manager as the asserted census. Negative controls should corrupt the bucket head, next index, occupied bit and generation independently. Production must reject unreadable or inconsistent backing and cycles by a finite bound; matching entry/return reads alone do not establish allocation generation or writer exclusion.
