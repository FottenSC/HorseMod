# Scheduled rolling startup ownership — 2026-09-28

`BeginRollingSchedule` previously called `RollingOperation(Begin)` before moving the prepared correction schedule into the host or initializing `ReplayRollingInputHistory`. `RollingOperation` requests the first forward tick. If that request observes an input boundary synchronously, the schedule/history are absent. `AdmissionBytes` also charges only `rolling_.schedule`, so the local allocation was not charged during the first request.

The production method now publishes the owned schedule and initializes tick/sample history before calling `RollingOperation`. On an idle startup rejection it releases both. If startup has already moved into a failed phase, it retains both for the existing terminal owner; the regression does not claim complete-B recovery. The first expected revision is checked against the checkpoint before this publication.

The native-contract fixture extracts the actual `BeginRollingSchedule` method and has its first forward request inspect schedule ownership, charged budget and initialized history, then record a synchronous first consumption. It covers success, rejection before start, a failed startup after the first consumption, and stale initial revision. Its [failing-before receipt](../../build_cmake_LessEqual421__Shipping__Win64/replay-tests/evidence/manifests/cc32ef3743905fe99687f3e75fbae9f118f6dc91333e800d1c2ea1752580cc3c.json) reaches the intended ownership/history assertion. The [four current-source focused input cases](../../build_cmake_LessEqual421__Shipping__Win64/replay-tests/evidence/manifests/a9bb138cab8e9d91c1db20e25587a7699cb1cedd7f79f882d36eb7bec34afa68.json) pass after the fix; the [native build and two CTests](../../build_cmake_LessEqual421__Shipping__Win64/replay-tests/evidence/manifests/50c028dec162ae6755d90364f6048894d1a515d6404ab535ea5bc4ab35250509.json) also pass.

This closes a local startup ordering defect only. It does not establish G0 task safety, live first-consumption mapping, complete B recovery, normal-render coherence, 1 GiB total ownership or full-update cost. No deployment or live correction was attempted.
