## Native and asset evidence

The [outgoing-consumer audit](rollback-debris-motion-consumers-2026-09-28.md) traces `142028750` body output through child movement `141DA43E0`, overlap update `141DB1200`, and conditional child `+0x460 = 141DB1CD0`. When child `+0x48 & 0x40` is set, this route can update physics-volume ownership and dispatch callbacks despite PhysicsOnly collision and empty overlaps. The generated `SceneComponent` declaration calls this flag `bShouldUpdatePhysicsVolume` and gives a false constructor default; generated declarations do not prove an A617 instance value. The selected A617 historical raw log has no retained value for this byte.

A read-only exact-name scan searched ASCII and UTF-16LE `GetGroundDebris` and `NiagaraDataInterfaceStaticMesh` in all 48,869 `.uasset`/`.umap` package headers under the external SoulcaliburVI `Content` dump: zero hits. A second scan of `.uexp` payloads in `Battle`, `Stage`, `VFX`, and `Chara` likewise found zero hits, including selected stage 9 and its character directories. These scans constrain authored direct references in those files; dynamic/reflected binding, active runtime Niagara instances, and packages outside the payload subset remain unproved. No external dump file was copied into the repository.

For the separate mid-update RED, Ghidra shows `ExecuteTickFunctionGraphTask @14215ED20` runs the task body `14215D250`, then completes the graph event through `140D20A70`, releases its event reference and recycles the task. The task destructor target `142158AF0` releases an event reference without graph-event completion. Neither routine supplies a verified abort-to-quiescence path for a popped, unentered world start-physics task. This is a narrow task-owner finding, not a general PhysX cancellation census.

The producer `QueueTickFunctionWithPrerequisitesForEpoch @142163BA0` stores the scheduled task at tick function `+0x18`, retains prerequisite completion events, and adds task/event references to sequencer group arrays. The body `14215D250` clears the tick binding only after the world start-physics callback returns. Dropping the popped task by destructor would therefore leave more than an allocation to retire: the tick binding, referenced graph event, sequencer entries and dependent work require an owned settlement protocol. No such abort path was identified in this bounded audit.

## Limits and next resolving fact

The new guard enforces the physics-volume branch only at its current call sites. It does not guard a flag change before native transform consumption, witness the actual A617 byte, close reflected/Niagara readers, or prove presentation-only motion. G0 remains open because the changed-free-body RED has no verified way to cancel a popped start task and recover complete B. The smallest next native question is the concrete owner and graph-event obligations of **that unentered task**, and whether a legitimate abort/settlement path exists without executing rejected physics. Keep complete B until corrected execution and application/render completion; do not signal a task as complete or treat a held task as canceled. No live A617 witness is source-qualified while this RED persists.
