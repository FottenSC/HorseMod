## Filter, bounds and interpretation

The observer learns opaque scene addresses at entry to the already-owned startup/shutdown broadcasts or dispatches whose collection is exactly scene+0x10/+0x80. It retains at most 32 addresses in an append-only atomic registry, with no native memory lookup and no eviction. Writer matching uses collection address alone, not a caller allowlist: the vehicle path, other callers, foreign threads and calls outside lifecycle/dispatch can all be recorded once the address has been discovered. Unmatched writer calls take a bounded 32-slot scan while observation is active, without locking, stack capture or file I/O; inactive calls take the accepting-flag check. Both global hooks remain pinned and forwarding when inactive.

Matching events contain collection, correlated opaque scene, raw receiver and method for registration, the output-pointer/removal-handle argument, direct return caller, thread, pair/parent/depth, observed overlap and up to eight raw unwind frames. Return events reuse the saved entry ancestry and arguments. Registration additionally records its actual returned pointer and a guarded eight-byte `ReadProcessMemory` copy of the output handle, with an explicit read-success flag. Removal has no receiver argument; its receiver cannot be inferred when the registration predates coverage. No scene, collection, callable or receiver is dereferenced on return. The writer ABI supplies no scene selector or delta: writer `scene_type=UINT_MAX` explicitly means unknown and delta is zero, not an observed type-0 dispatch.

The shared event limit remains 16,384. At most 128 observed calls can be pending concurrently; registry, event or pending-slot exhaustion sets the sticky drop/invalidity state while native forwarding continues. A failed unwind or guarded handle read also invalidates completeness. Entry reservation retains room for the paired return. Closing with a writer pending seals further observation but does not cancel it: the return is retained in the staging file and the phase cannot become complete later. Serialization, write and flush failures remain sticky. The observation charge stays at the existing 2 MiB, with a compile-time storage/stack accounting assertion; the permanent owner separately adds two detour charges.

Coverage starts only after observer admission **and each scene's first qualifying observed entry**. Earlier startup, earlier writers and calls already in progress are not covered. Scene addresses are not generations or lifetime leases and can alias after reuse; shutdown does not justify dropping an address. No epoch, simulation tick or enclosing task is invented from raw pointers. The run identifier, process/image identity, timestamps and saved ancestry allow offline correlation, but do not prove task ownership. Other mutation primitives/direct writes are not universally covered. Header flags keep `writer_coverage_proven`, `whole_process_coverage`, `native_quiescence_proven`, `lifetime_proven` and `recovery_proven` false, and explicitly state `pre_discovery_writers_covered=false`. A zero-writer result cannot close G1.
