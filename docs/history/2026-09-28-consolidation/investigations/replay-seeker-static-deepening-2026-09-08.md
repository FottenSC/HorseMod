## Failure ownership extends beyond the GPU event

`ReplayGpuCompletion` distinguishes submission from retirement correctly: timeout/cancellation retains in-flight resources, and a later observed signal retires the event without turning the failed request into success. A device-removed error ends the device's in-flight ownership without claiming successful copy completion. `Sc6ReplayParticleCopy::Poll` keeps the failure until retirement and then permits undo where native state is still reversible. `RestoreUndo` gives recovery its own deadline and preserves the original error; it refuses once coordinate commit has started. The enclosing state machine still needs a recoverable terminal owner. `AdvanceHistoricalRestore` immediately returns for phaseFailed. `Cancel` can set the flag in that phase, but does not restart recovery; `Stop` refuses any extant historical transaction or unreleased particle owner. A failure while already Committing is marked terminal, including failures after B storage has been retired. This correctly prevents partially restored resume, but does not itself drain all retained work or provide clean exit/re-entry. Retiring GPU work needs an independently progressing owner even when the restore operation has failed; otherwise retaining resources becomes an indefinite blocked session rather than recovery.

There is also a destructor hazard at the API boundary. `Sc6ReplayHost::~Sc6ReplayHost` calls `Stop()` and ignores false. `DeterministicHookSet::~DeterministicHookSet` calls `Uninstall()`, whose first action returns early if host.Stop fails. The normal bounded harness may never destroy this object in such a state; this is a statically reachable API/teardown risk, not a demonstrated failure in the retained successful runs. A session quarantine must retain the **whole execution owner and module/callback lifetime**, not merely leak one texture or task pointer. Never destroy a native task payload's `this` while its surface/RHI command or completion event remains live.

The existing Release predicate checks several dirty flags and native published participants, but is not a complete terminal-state proof: it omits explicit terminal phase, surface/RHI/event retirement, and some source/execution/HUD/trace/render dirty ownership. Tighten release around one consolidated ownership invariant. Pin the borrowed A checkpoint until that invariant holds. Use a commit cursor for post-cancellation irreversible retirement; do not attempt B undo after a participant has already freed B unless that participant explicitly supports it. Validate commit phase and required pointers **before** dereferencing target/physics_observation in `RestoreOperation(Commit)`.

For the first arbitrary-tick integration, retaining completed-application checkpoints and resimulating forward to an externally held interior tick is a coherent smaller route than transplanting a historical pending task. It still requires immutable checkpoint-owned GPU images, no-birth handling, exact source revision and all future-affecting owners, plus cancellation that recovers the original B. It does **not** validate direct historical interior snapshot installation: current RestoreContinuation admits only the same RepeatDecision continuation with the tick field changed, while RestoreIdleContinuation requires both sides Idle with no handler. Keep those restrictions until their larger pending-work ownership is implemented. Report checkpoint coverage and target coverage separately; sparse completed checkpoints can cover interior targets without pretending those targets are all directly capturable.

The legacy SimulationSession/ReplayCoordinator API is not a replacement for this host. Its RestoreAndResimulate loops one adapter AdvanceFrame per numeric frame, has synchronous local undo, and returns Running after reconciliation. It cannot represent the new native application/world/task/GPU transaction simply because its names resemble the desired interface. Its source reachability is through ReplayCoordinator; preserve the strict legacy entry point until replacement is verified, but put new public Capture/Restore/AdvanceToTick/Resume/Stop requests on the existing Sc6ReplayHost owner. Do not create a third competing coordinator or revive legacy journals as hidden dependencies.

## Memory spacing and latency must be solved together

The currently admitted six1024x1024 single-mip GPU textures require56MiB of pixel payload per retained particle image: two16-byte position textures, two8-byte velocity textures and two4-byte attribute textures per texel. This follows directly from ParticleCopy.hpp formats and BeginUnchecked's dimensions/sample/mip admission. It excludes driver/resource overhead, CPU checkpoint state, other visual histories and scratch. With this unchanged design,512MiB cannot hold more than nine such A images even with every other owner omitted, or eight after reserving just one56MiB B image. Those are deliberately generous arithmetic upper bounds, not actual usable retention counts. The current233,662,524-byte bounded transaction and its136,893,200 reported GPU bytes include additional owners and are not a per-checkpoint size to multiply blindly.

For a checkpoint gapD, the simple necessary budget is `fixed restore/publication cost + D / measured unpaced tick throughput <= 0.5 seconds`, including final readiness and any round work. It is not sufficient where cost varies by event/phase, but it exposes the tradeoff before a large index is built. Measure actual worst gaps, all retained/scratch/undo/quarantine bytes and request-to-ready latency. Increasing spacing to meet memory while leaving native60Hz pacing cannot preserve the strict seek ceiling for long gaps. Conversely, allocating more snapshots until latency improves cannot exceed512MiB. The current paced five-tick timing does not supply the missing unpaced throughput.

Possible optimizations must follow ownership evidence: reuse prepared storage and leases where identities/capacities remain valid; remove diagnostic readbacks; rebuild verified derived outputs; reduce purely visual history only after consumer classification. Do not discard persistent particle integration textures or original B merely because they are large, reuse a mutable singleton image for several checkpoint handles, or feed historical GPU outputs into changed-input continuation. First provide the correct bounded seeker and an honest capacity/latency result, then optimize the measured cost while retaining the requirement. This arithmetic is static planning evidence, not a new performance run.
