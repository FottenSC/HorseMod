## Replacement contracts

1. Keep an immutable authored replay reference. Seek restores both simulation and local replay-source continuation. Fresh producer output is observed and compared, never overwritten to manufacture agreement with the reference. Native positions, hit outcomes and source inputs must agree with uninterrupted playback.
2. Represent input epochs explicitly inside the existing native batch record. An epoch has a stable session/input identity, publication ordinal, input pair, observed coordinate span, completed epilogue, canonical identity and reconstruction token. A native coordinate is not a Gekko input index.
3. Save/load, confirmation, presentation commitment, retention and generation replacement resolve through that same epoch record. Outstanding tokens retain generation/revision and required storage. Corrected inputs may change speculative execution spans; predicted geometry cannot be an immutable correctness requirement.
4. Keep waiting at the verified engine boundary. Pending acknowledgment retains one fixed frontier and one submission. Enter, active, failure, quiescence, scene replacement, teardown and re-entry use explicit transitions.
5. A capture owns its actual deployment and process. Before gameplay evidence is accepted, the requested bytes must match the file mapped by the owned game process. The deployment owns one durable recovery journal across report filenames. A unique process argument plus executable and creation time identifies a launch interrupted before PID registration.
6. Evidence states what was observed. Sealed logs and exact loaded binary identity are prerequisites. Requested depths, self-generated hashes, cumulative presentation totals and a live impairment helper are insufficient.
