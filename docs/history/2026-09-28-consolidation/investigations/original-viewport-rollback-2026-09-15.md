# Original viewport rollback publication

The earlier `PresentHook::prepare_replay_output` created a second HWND and swap chain. Production now uses the original game window and swap chain throughout the transaction; the old diagnostic helper remains retained but is not called by production.

The bounded replacement uses the original swap chain's buffer zero. A paused draw saves its native contents to independently owned GPU scratch, copies the retained display image, draws the overlay and calls the existing Present chain, then restores the native contents. Completion of the restoration copy is required before releasing scratch or allowing native work to resume. The existing render-thread affinity and pipeline-state save/restore remain required. A failed Present still needs restoration and GPU retirement; a timeout retains all resources.

This path will initially admit the windowed bitblt DISCARD configuration only, with explicit device, HWND, shape and buffer identity checks. Microsoft's [swap-effect contract](https://learn.microsoft.com/en-us/windows/win32/api/dxgi/ne-dxgi-dxgi_swap_effect) says DISCARD contents are undefined after Present; therefore merely drawing into the native buffer and hoping its contents survive is insufficient. [GetBuffer](https://learn.microsoft.com/en-us/windows/win32/api/dxgi/nf-dxgi-idxgiswapchain-getbuffer) exposes buffer zero for DISCARD. Flip-model and exclusive-fullscreen behavior need separate evidence and must not be silently assumed equivalent.

The display transaction is distinct from simulation restoration. While A and corrected execution are uncommitted, ordinary native Present attempts must not expose intermediate images. The last validated B remains displayed. Required native render work and capture still run. After C settlement and target-tail completion, publication through the original swap chain must finish while B recovery remains available, before the irreversible commit decision. Recovery likewise keeps B display ownership until coherent B restoration completes. Neither a pre-Present texture capture nor a held redraw is proof of regenerated scene coherence.

The implementation has passed production-method WARP copy/restoration and publication-gate tests. Bounded native attempts have displayed held B through the original HWND with backbuffer restoration and GPU completion. They currently reject during trace preparation, so corrected-C scene coherence and sustained performance remain unqualified. See [current status](../../../rollback-status.md) for retained runs. Actual displayed frames, suppressed attempts and deliberately held time must be reported separately. The extra scratch and all in-flight references belong in the existing ownership accounting.
