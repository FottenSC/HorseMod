# Class-Centric Browse Plan

Goal: make the Visual Studio export easier to browse by generating class-centric files and richer function headers from the same repeatable export pipeline.

Status: implemented in `tools/build_browse_tree.py` on 2026-06-25.

This plan intentionally uses generated data only. After Ghidra names, prototypes, namespaces, comments, or types improve, rerun:

```powershell
E:\myMods\ghidraCalibur\tools\refresh_ghidra_calibur.ps1
```

and the class browse tree should be regenerated deterministically.

## Scope

- Add `browse/classes/<ClassName>.cpp` files.
- Add a generated header comment before every function block.
- Keep existing `browse/named` and `browse/address_ranges` views unless we later decide the class view fully replaces them.
- Do not track "original name" separately. The header should show the current Ghidra name only.
- Do not require manual edits to generated files.

## Inputs

- `exported/sc6_decompiled.cpp`
  - Source of decompiled function bodies.
- `exported/functions.csv`
  - Source of current Ghidra function metadata.
  - Already generated by `ExportFunctionIndex.java` / `RunCppExporter.java`.

Future optional inputs can be added, but the first version should not depend on them:

- `exported/comments.csv`
- `exported/xrefs.csv`
- `exported/types.csv`
- `overrides/classes.yml`

## Function Header Format

Each generated function block should start with a compact, stable header:

```cpp
// GhidraCalibur Function
// Address: 0x140947840
// Name: FUN_140947840
// Class: ALuxBattlePauseController
// Category: UE
// Signature: undefined8 * FUN_140947840(undefined8 *param_1, undefined8 param_2, undefined8 param_3, undefined4 param_4)
// Raw export lines: 1548207-1548221
```

Rules:

- `Name` is the current Ghidra name from metadata or the parsed function name.
- No `Original` field.
- `Class` is omitted when no class can be inferred.
- `Signature` is omitted when unavailable.
- Keep the existing `#pragma region` wrapper so Visual Studio folding remains useful.

## Class Inference

Add a deterministic `infer_class_for(block, meta)` step in `tools/build_browse_tree.py`.

Use these sources in priority order:

1. Metadata namespace if it looks like a UE/C++ class name.
2. Current function name patterns:
   - `ClassName::MethodName`
   - `GetPrivateStaticClassBody_<ClassName>`
   - `Z_Construct_UClass_<ClassName>`
   - `Z_Construct_UClass_<ClassName>_Statics`
   - `RegisterNatives<ClassName>`
   - names containing `_A...`, `_U...`, `_F...`, or `_I...` class-like tokens.
3. Wide or narrow string literals in the first part of the function body:
   - `L"ALuxBattlePauseController"`
   - `"ULuxGameInstance"`
4. Optional future override map if present.

Keep inference conservative. If multiple possible classes are found and no source clearly wins, leave the function out of `browse/classes` and keep it in the existing category/address views.

## Class File Generation

Add `write_class_files(blocks, browse_dir, source_cpp, max_functions_per_class_file)`:

- Group blocks by inferred class.
- Sort functions inside each class file by address when available, otherwise by current name.
- Write one file per class for normal-sized classes.
- If a class has too many functions, split deterministically:

```text
browse/classes/ULargeClass/ULargeClass_001.cpp
browse/classes/ULargeClass/ULargeClass_002.cpp
```

- The same function may appear in both `browse/classes` and the existing category/address views. This is intentional for browsing.
- Record the class placement in `index/class_members.csv`.

## Index Updates

Extend `write_index` to produce:

```text
index/classes.md
index/class_members.csv
```

`classes.md` should include:

- class name
- function count
- first address
- generated browse path
- categories represented

`class_members.csv` should include:

```csv
class,address,name,category,signature,browse_file,browse_line
```

This gives us a stable audit trail when Ghidra data improves.

## Visual Studio Project Updates

Update `filter_for(path)` and `write_vs_project()`:

- Put `browse/classes/*.cpp` under `Browse\Classes`.
- Add nested filters for split large classes if needed.
- Keep all generated class files excluded from build.

Because the `.vcxproj` uses explicit entries, a refresh should make Visual Studio show new class files after project reload.

## Reproducibility Rules

- All generated class files must be deleted and rebuilt during every refresh.
- Class inference must be based only on exported data plus checked-in override files.
- Generated file order must be stable:
  - sort classes by name
  - sort functions by address/name
  - sort index rows
- Do not hand-edit anything under `browse/` or `index/`.
- Store any durable manual corrections in an override file, not generated output.

## Implementation Steps

1. Extend `FunctionMeta` and `FunctionBlock` with `signature`, `namespace`, and `class_name` usage where needed.
2. Add class-name extraction helpers to `build_browse_tree.py`.
3. Add generated function headers to `write_chunk`.
4. Add `write_class_files`.
5. Add `index/classes.md` and `index/class_members.csv`.
6. Update Visual Studio filter generation for `browse/classes`.
7. Run `refresh_ghidra_calibur.ps1 -KeepRawExport` during development for faster iteration.
8. Verify:
   - Python compile succeeds.
   - `.vcxproj` and `.filters` parse as XML.
   - `browse/classes` contains expected UE classes.
   - Visual Studio shows files under `Browse\Classes`.
9. Run a normal refresh without `-KeepRawExport` to confirm the final workflow still cleans large raw files.
