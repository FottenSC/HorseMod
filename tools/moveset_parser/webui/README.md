# SC6 Moveset Web UI

A modder-friendly browser for the parsed SC6 moveset data. Built on
[TanStack Router](https://tanstack.com/router) (file-based routing) on
top of plain Vite + React — no SSR, no server runtime, just a static
SPA. Run locally; `vite build` produces a `dist/` folder you can serve
anywhere.

The Python parser (`../luxformats.py`) is the source of truth; this UI
reads a pre-exported JSON snapshot of every character.

## Quick start

```sh
# 1. Export the data from .khd/.mot/.dtp/.dat → JSON
python ../export_webui_data.py           # writes to public/data/

# 2. Install deps + run the dev server
npm install                              # first time only
npm run dev                              # http://localhost:3000
```

Re-run `export_webui_data.py` any time the parser or the source `.khd`
files change. The web app reads JSON only — no Python at runtime.

## Design principles

- **Modder-first.** The Moves tab is the default; you see attack class,
  damage, startup, on-hit/on-block, range. Engine field names (the
  `wU16AttackFlags`-level stuff) are hidden behind an "engine fields"
  toggle on the per-move page.
- **Plain English everywhere.** Cell roles (`Attack` / `Header` /
  `Sentinel`) are visible labels, not bit patterns. Range `-127`
  becomes `∞`. Attack class is one of `Mid / High / Low / Unblockable /
  Throw`.
- **Cross-linking.** Every cell shows which slots reference it via
  `nCellBoneIndexPerVariant`. Every slot can be linked from a move.
- **Honest about uncertainty.** DLC character IDs (`060`, `062`,
  `064`–`066`) ship with best-guess names and a `?` marker — fix names
  in `../export_webui_data.py` (`CHARA_NAMES`) and re-export.

## Phases implemented

- **Phase 1** — Character roster + tabbed layout with file-presence
  badges and per-char stats (attack count, top damage, slot count).
- **Phase 2** — Moves tab with class / minimum-damage / role filter
  chips and column sorting (idx, class, damage, startup, on-block,
  on-hit, range).
- **Phase 3** — Per-move detail page leading with a quick-read panel
  (class, damage, startup, advantage, range), followed by hit-reaction
  details and cross-linked slots. Engine struct fields collapsed by
  default.

## Future phases (not yet implemented)

- **Phase 4** — Global search across moves (cross-char queries like
  "all 50+ damage Low attacks").
- **Phase 5** — Skeleton + hitbox visualisation per character.
- **Move-state graph** — render `slot → next_move_id` edges extracted
  from `TransitionAuthor` CALLCOND args as an interactive DAG.

## Caveats

- `On-hit` and `On-block` numbers are **raw stun frames from the cell**,
  not classic frame advantage (`stun - attacker_recovery`). Computing
  true advantage requires the per-slot bytecode trace which the parser
  doesn't fully evaluate yet. We mark them as `stun` in tooltips.
- Some attack-flag bits (`0x004 / 0x008 / 0x010 / 0x020 / 0x040 / 0x100`)
  are observed on disk but their semantics aren't fully verified. The
  parser renders them as `bN` rather than guessing.
- DLC character names are best-guesses where flagged with `?`.
